There's a new reason to build small: coding agents. A stack that fits in your head also fits in your agent's context window, so both of you can reason about the whole thing.

Shibumi keeps it that way: one curated library per job, every feature as readable source, and a deploy path you own end to end. Simplicity, patience, humility.

One command, a whole app

bun create shibumi writes a complete project from a short list of curated parts, one library per job: Hono for routes, Alpine for browser behavior, Zod for validation, SQLite and Drizzle when you need data.

Pick a size: static output, web app, or full stack. What lands in your repo is plain source: routes, styles, tests, a Dockerfile, a deploy script, and an agents.md with the house rules for your coding agent.

Add features as source

When you need auth, email, or uploads, bun run shibumi add copies readable .ts files, migrations, and tests into your repo instead of adding a dependency. There's no framework underneath to outgrow.

Each extension also writes its rules: agents/auth.md merges into the root agents.md, so your coding agent learns the feature the moment the code lands. The installer previews every write and stops on conflicts.

Ship to a server you own

Rent a €5 VPS or use your homelab: shibumi-server hosts every app you build. Install pinned v{{server-version}} on the Linux host with curl -fsSL https://shibumistack.dev/install/server | bash.

Then run bun ship, included in every generated project. It builds the exact committed code on your machine and deploys it:

The server verifies commit, image identity, and health before swapping behind Caddy, and keeps a rollback image for 12 hours. Existing projects get the same command from one installer. Read the deployment flow →

One small thing on the side: static Shibumi sites can still have working forms. Point a plain HTML form at Shibumi Forms and submissions work, without a clunky embed or another paid service. It runs today at forms.shibumistack.dev.
