create-shibumi creates a SQLite full-stack app, an blog, or a static site. All three include VPS deployment, and bun create shibumi . adds that deployment to a project that already exists.

Product choices.

Generated source

Write files instead of adding a runtime.

Routes, tests, config, and deployment code stay in the app and import the selected libraries directly.

Three options

Choose a starting point.

Run a full-stack app with SQLite, publish an blog, or ship any framework's static build output.

bun create shibumi@latest my-app
cd my-app
bun dev
Extensions

Copy feature code.

An extension adds its routes, config, migrations, tests, and agent instructions. The app can edit or remove them.

Agents

Keep project rules in the repository.

Root agents.md records shared conventions. Extensions keep named guides under agents/.

Security

Generate checks at each boundary.

Relevant generated projects include request validation, secure headers, CSRF checks, loopback port binding, and secret-safe config.

Extensions.

Bundled extensions copy reviewed source, migrations, tests, and named agent instructions into the app.

Install previews writes, stops on conflicts, and produces the same result when repeated.

Manifest

Declare compatibility and effects.

The manifest names package compatibility, target files, dependencies, environment keys, migrations, agent guides, and checks.

Files

Every write has a target path.

Install lists new files and exact edits before changing the project. Unexpected source stops the operation.

Prompts

Store choices in generated config.

Provider and storage answers become reviewable project files.

Agents

Keep guidance beside the feature.

A named file under agents/ records routes, helpers, tests, and files that need extra care.

Checks

Install packages into fixture apps.

Registry checks reject undeclared writes, network access during installation, lifecycle scripts, duplicate hooks, and paths outside the project root.

{
  "name": "auth",
  "title": "Auth",
  "type": "official",
  "compatibility": {
    "shibumi": ">=0.1.0",
    "projects": ["full-stack"],
    "deploy": ["self-hosted"]
  },
  "files": [{ "from": "files/src/lib/session.ts", "to": "src/lib/session.ts" }],
  "agents": ["agents.md"],
  "env": ["SESSION_SECRET"],
  "checks": ["bun test"]
}

Deploy targets.

VPS deployment is supported. Other providers wait until their generated projects pass equivalent artifact and deployment tests.

  • VPSSupported. Rootless Podman, Compose, persistent volumes, Caddy, and systemd.
  • Other providersPlanned. Fly.io, Cloudflare, and Vercel remain unsupported.
