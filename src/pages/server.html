shibumi-server is a small, experimental Bun service for one job: turn a signed push into a tested container on your own VPS.

Open source · dogfooding now

Planned install

Set it up once.

The installer will place a pinned copy on the host and create a systemd service. Caddy stays public; the receiver and every app port stay on loopback.

$ bunx shibumi-server init
checking   Caddy + rootless Podman
installing pinned system service
ready      waiting for signed webhooks

A push, seven deliberate steps

The VPS is the CI.

  1. 01

    Verify

    Check the GitHub HMAC over the raw body, then match the configured repository and exact branch.

  2. 02

    Lock

    One deployment per app. A second request receives 409 Conflict; nothing waits in a hidden queue.

  3. 03

    Preflight

    Require enough available memory and disk before changing the checkout. A constrained host refuses the build.

  4. 04

    Fetch

    Fetch the branch and require its commit to match the signed webhook SHA. No ambiguous git pull.

  5. 05

    Build

    Build with rootless Podman under a deadline and systemd ceilings while the current container keeps serving traffic.

  6. 06

    Test

    Run the app's configured checks inside the new image. A failure stops before replacement.

  7. 07

    Start

    Start the replacement on its explicit localhost port and poll its health endpoint.

Clear boundary

Public code. Private machine.

In Git

Everything reusable.

  • Server and CLI source
  • Container and Compose templates
  • Configuration schema
  • Caddy and systemd examples
  • Tests and security model
On the VPS

Everything specific.

  • Webhook HMAC secrets
  • Repository credentials
  • App paths and assigned ports
  • Environment files and data
  • Deployment state and logs

Multiple apps

Caddy knows the port because you tell it.

Each app receives an explicit localhost port in machine-local config. Caddy maps the public domain to that port. Databases and workers remain private inside the Compose network.

myapp.com {
  reverse_proxy 127.0.0.1:9100
}

another.app {
  reverse_proxy 127.0.0.1:9101
}
