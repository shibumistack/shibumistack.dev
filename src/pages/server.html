Small on purpose

No dashboard.
No hidden deploy platform.

shibumi-server verifies GitHub's HMAC over the raw request body, rejects replayed delivery IDs, fetches the exact signed commit, and runs configured build and test commands as argument arrays. Caddy remains the public edge. Podman remains rootless. The files remain yours.

01

Signed only.

Malformed hooks are rejected early. A valid secret, repository, branch, full commit SHA, and new delivery ID are all required.

02

The host gets a vote.

Memory and disk preflight, a build deadline, process cancellation, and systemd ceilings stop unsafe work before startup.

03

One deploy at a time.

Per-app locks return 409 Conflict for concurrent work. Failed fetches, builds, and tests never run compose up.

Dogfooding with MCPVault

The test found the limit.

We connected an isolated test branch from MCPVault, the open-source MCP bridge for Obsidian, to the real webhook path. Signature verification, exact repository and branch checks, commit matching, and deterministic checkout all passed. The build started from the signed commit.

Then the existing framework-heavy website build proved too large for a small production VPS. That was useful failure, not a launch: we stopped, cleaned up the test, and added memory and disk preflight, build cancellation, and hard service limits before trying again.

The next live dogfood uses the tiny Bun fixture or MCPVault's future lightweight Shibumi app—not the current heavy build. Production apps keep serving while these isolated deploy tests continue.

Pinned installer

Installed once.
Downloaded never.

The v0.1 installer is implemented and awaiting package publication. init copies an exact version to the host and writes mode-restricted config, secrets, and a resource-limited systemd user service. Restarts execute that local copy—never an unpinned download.

› bunx shibumi-server@0.1.0 init
› bunx shibumi-server@0.1.0 add example.com \
    --repository owner/repository \
    --checkout /srv/shibumi/apps/example-com \
    --port 9100 -- bun test

Caddy routes and GitHub webhook settings remain explicit operator steps. Secrets and machine inventory never enter the public repository.
