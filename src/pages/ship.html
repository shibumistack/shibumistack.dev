01

Connect

Run one installer.

Run this from your project root. The shell downloads reviewed TypeScript to a temporary file, Bun runs it with terminal prompts, then the file is removed.

curl -fsSL https://shibumistack.dev/install/ship.sh | sh

The installer validates your Git project, adds owned ship source and package commands, then connects setup. Existing edits to scripts/ship.ts are never overwritten.

Setup suggests the domain, asks once for your normal user@server target or SSH alias, and registers the current branch. Choose Run bun ship (recommended) or Deploy every GitHub push. Rerun bun ship:setup anytime to switch.

If no tracked Compose file exists, setup offers to generate a bounded Bun Dockerfile, loopback-only compose.yaml, and secret-safe .dockerignore. Review, commit, and push them, then resume with bun ship:setup. Existing files are never overwritten.

Choosing Run bun ship disables the matching webhook and deploys over SSH. Choosing Deploy every GitHub push creates, enables, or repairs it. Setup keeps owned files when DNS or another external prerequisite is pending.

Cloudflare: Deploy-on-push requires Full (strict) SSL/TLS mode for proxied domains.

03

Deploy

Push when ready.

bun ship

Ship checks for a reviewed client update before tests or builds. It can use the latest immutable version immediately, then updates tracked scripts/ship.ts only after deployment succeeds. The change stays unstaged for review and commit.

Ship requires committed work on the configured branch. It runs project tests and checks, builds the server's Linux image from exact HEAD, labels it with repository, app, revision, source tree, and platform identity, then uploads it through SSH. Only after upload succeeds does it push Git. Recommended mode then triggers the exact deployment over SSH. Server independently verifies every label before deployment. Ship never stages or commits files for you.

Docker cache stays enabled by default. Use bun ship --rebuild to pass --no-cache for suspected cache or mutable-input problems.

Existing domains keep their current Caddy upstream until first Shibumi deployment passes health checks and you approve cutover. Use bun ship:status for latest deployment state, bun ship:logs for its log, or bun ship --rollback to restore previous retained image.

Agents can use bun ship -y for a prompt-free run. -y is short for --yes. Bun forwards it directly, so no -- separator is needed. Safety checks and failures remain active.
